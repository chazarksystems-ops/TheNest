# P6 — Baseline Comparison

Benchmarks in TheNest are advisory performance measurements. They help detect significant regressions in core logic but are **not a required gate** for commits or packaging.

---

## How to run benchmarks

```powershell
cargo bench
```

Or via the validation script:

```powershell
.\scripts\validate.ps1 -Bench
```

---

## What is measured

| Benchmark | What it measures |
|---|---|
| `nociceptor_bench` | Time to compute a suffering score from weighted metrics |
| `worker_tick_bench` | Time to execute a full worker tick (score + threshold check) |
| `receipt_json_bench` | Time to serialize an `EpigeneticPayload` receipt to JSON |

---

## Where results are stored

Criterion writes benchmark reports to:

```
target/criterion/
```

Historical baseline summaries (for documentation purposes) are stored in:

```
reports/benchmarks/
```

These summary files are maintained manually. They are not auto-generated by `cargo bench`.

---

## What is concerning

- A regression of **>2x** in `nociceptor_bench` or `worker_tick_bench` warrants investigation — these are the hot paths in score calculation.
- A regression of **>2x** in `receipt_json_bench` may indicate unintended allocation or serialization bloat.

## What is not concerning

- Minor timing variations across runs (±10–20%) are normal and expected.
- Variation due to system load, thermal state, or background processes is not meaningful.

---

## Policy

> [!IMPORTANT]
> Benchmark timing is **not** a required gate for commits. A benchmark regression does not block packaging or handoff — it is a signal to investigate, not a hard failure.

If a benchmark shows a significant regression, investigate the cause before continuing feature work. Document findings in `reports/benchmarks/`.
